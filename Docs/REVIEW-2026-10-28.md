# Espresso Escape review — 2026-10-28

Snapshot of `unity` at `9c4ecda3708496eddfcb405573c53c98ed88d4f4` (Unity `6000.6.4f1`, URP `17.6.0`). Findings below are from this tree only. Line numbers are from that snapshot.

This is not a ship report. The playable scene does not run the per-level prop sets, L5's boss flag does not change the level, and the new gravity test fails against the catalog as written. Unity is not installed in the environment that wrote this file, so the test suite was not executed.

## Rank

- **P0** — the built scene does not play five distinct levels.
- **P1** — a top-chart iOS build would be rejected, oversized, or missing a real finale.
- **P2** — real code risk or cost that does not by itself block a build.

Checked and holding, so they are not listed as bugs: the bean Rigidbody in `Assets/Escape.unity` is interpolated and continuous; fixed timestep is 50 Hz; play input is touch plus mouse; the title UI reads `Screen.safeArea`; `LevelCatalog.LevelCount` is 5; `Make(5).bossBeat` is true; `goalZ` and `obstacleDensity` rise across the five `Make` rows.

### 6. Gravity is not a difficulty axis

`Make` sets `gravityScale = 1f` on all five rows (`LevelCatalog.cs:39`, `:46`, `:53`, `:60`, `:67`). The comment at `:31-32` says that is deliberate so airtime stays about 0.52 s. `GameSession.Awake` says the same and forces a rebuild so an old 1.02–1.10 curve cannot survive (`GameSession.cs:28-30`). `LevelRunner.LoadLevel` then assigns `Physics.gravity = (0, -22, 0)` and does not multiply by `gravityScale` (`LevelRunner.cs:108-109`).

`goalZ` (14, 22, 28, 34, 48) and `obstacleDensity` (0.35, 0.50, 0.62, 0.74, 0.88) do strictly increase. Gravity does not. The comment and the code agree with each other. They do not agree with a strictly ascending gravity contract. `GravityScale_StrictlyAscending` in `Assets/Tests` encodes that contract and fails on this data. It was not run here.

### 7. `LevelCatalog.Get` treats a blank five-slot array as ready

The field initializer is `levels = new LevelDef[LevelCount]` (`LevelCatalog.cs:25`). A fresh instance already has length 5, filled with default structs (`title` null, `goalZ` 0, `bossBeat` false). `Get` rebuilds only when the array is null or the length is not 5 (`:81-83`), so it returns those zeros. `Search` has the same guard (`:88`) and then calls `L.title.ToLowerInvariant()` and `L.pack.ToLowerInvariant()` (`:115-116`), which throw if title or pack is null.

`GameSession.Awake` does call `RebuildAll` (`GameSession.cs:30`) before play, and `SearchMenu` calls `LevelCatalog.Make` directly (`SearchMenu.cs:21`). The play path is covered. Any caller that uses `Get` or `Search` on a new instance without `RebuildAll` is not. There is no `LevelCatalog` asset in the repo.

### 8. No OS pause handler

A search of `Assets/**/*.cs` found no `OnApplicationPause` and no `OnApplicationFocus`. The pause overlay only sets `Time.timeScale = 0` (`TitleFlow.cs:272`) and restores it on resume (`:284`, `:291`). `runInBackground` is 0 (`ProjectSettings.asset:90`), so iOS suspends the player. `Maximum Allowed Timestep` is `0.33333334` (`ProjectSettings/TimeManager.asset:12`). On resume the bean can receive up to a third of a second of physics in one frame. Nothing zeroes `linearVelocity` across that boundary. `iOSRenderExtraFrameOnPause` is 0 (`ProjectSettings.asset:249`).

### 9. Run / walk split ignores the safe area

`TitleFlow.ApplySafeAreaPad` insets the canvas from `Screen.safeArea` (`TitleFlow.cs:567-585`) and `Update` reapplies it when the rect changes (`:93-94`). `BeanController.Update` splits run and walk at `Screen.width * 0.5f` (`BeanController.cs:143-151`). On a landscape iPhone the notch and home indicator eat one side of the full width, so the hold zones are not the safe-area halves.

Touch itself is implemented: every `TouchPhase` is handled (`BeanController.cs:105-121`), and mouse is ignored while `touchCount > 0` (`:124`). `activeInputHandler` is 0 (`ProjectSettings.asset:789`), which is the old Input Manager and matches `Input.GetTouch` / `Input.GetMouseButton`. The new Input System package is not in `Packages/manifest.json`.

### 10. Orientation is Auto Rotation, then a runtime lock

`defaultScreenOrientation` is 4 (`ProjectSettings.asset:11`). In Unity's `UIOrientation`, 4 is Auto Rotation. All four `allowedAutorotateTo*` flags are 1 (`:61-64`) and `useOSAutorotation` is 1 (`:65`). `GameSession.BootQuality` sets `Screen.orientation = LandscapeLeft` only when `Application.isMobilePlatform` (`GameSession.cs:46`). The player can open in portrait and snap after the first `Awake`.

### 11. The burlap floor texture is uncompressed and has no mips

`Assets/Resources/Look/tex-burlap.png.meta:9` has `enableMipMap: 0`. Default, Standalone, and WebGL platform blocks set `textureCompression: 0` (`:77`, `:90`, `:103`) and `maxTextureSize: 2048`. There is no `buildTarget: iPhone` block, so iOS inherits that default. The other `Resources/Look/tex-*.png` importers set `textureCompression: 1`. This file is the one `LevelRunner` loads for ground (`LevelRunner.cs:193`). A 2048 uncompressed RGBA texture with no mip chain aliases on the floor and stays large in memory.

`m_ActiveColorSpace` is 0 (`ProjectSettings.asset:49`), which is Gamma. That matches textures authored with `sRGBTexture: 1`. It is recorded here so a later linear switch is a look change, not a silent fix.

### 12. Device quality, URP, and Metal

- iPhone default quality index is 2 (`ProjectSettings/QualitySettings.asset:346`), the Medium tier (`:116`), which has hard shadows only (`shadows: 1` at `:118`). The manifest has the engine module `com.unity.modules.adaptiveperformance`, not the Adaptive Performance package, so that flag has no scaler to call.

## P2

### 13. Unity 6.6 find / instance-id APIs

Unity 6.5+ treats obsolete InstanceID APIs as compile errors, and the 6.6 manual marks `FindFirstObjectByType`, `FindObjectsByType(..., FindObjectsSortMode)`, and the `FindObjectsSortMode` enum obsolete. `GetInstanceID` is replaced by `GetEntityId`.

Compiled scripts under `Assets/` do not call `GetInstanceID`, `FindFirstObjectByType`, or `FindObjectsSortMode`. They call `FindAnyObjectByType` (for example `GameSession.cs:54-55`, `TitleFlow.cs:49`, `LevelRunner.cs:116`). `ImagineSet.Roots` uses the no-sort `FindObjectsByType<Transform>()` (`ImagineSet.cs:134`), which is the overload the 6.6 manual tells you to use.

Two files would be obsolete if they were compiled:

- `Assets/Scripts/_menu_wip/TitleFlow.cs.wip:28` calls `FindFirstObjectByType`. Unity does not compile `.wip`.
- `AgentScripts/PrepCapture.cs:9` calls `FindObjectsByType<Canvas>(FindObjectsSortMode.None)`. `AgentScripts/` is outside `Assets/`.

`ImagineSet.Align` (`ImagineSet.cs:19-48`) is the only caller of `Roots`, and nothing else in `Assets/Scripts` calls `Align`. It is not a per-frame find. If something starts calling it, it allocates an array of every `Transform`.

### 14. Per-frame cost

Steady play does not call `Find` or build strings inside `Update` once startup has finished.

- `LevelRunner.Update` (`:139-168`), `Pickup.Update` (`:26-31`), `ButtonPress.Update` (`:26-29`), and `BeanController.Update` (`:99-156`) do not allocate. A new `Pointer` is created only when a finger id is first seen (`BeanController.cs:161`).
- `TitleFlow.Update` calls `Camera.main` only until `TitleDolly` is added (`:84-91`). It calls `FindAnyObjectByType<LevelRunner>()` every frame while the HUD is active and `_runner` is still null (`:96-97`). `Start` assigns `_runner` at `:49`, so the per-frame find is the miss path.
- `AmbientMotion.Update` (`:93-148`) writes structs. `Shed` (`:151-182`) instantiates a leaf on a timer (`leafEverySeconds`), not every frame. `SetNameQuery` (`SetNameQuery.cs:5-7`) replaced the old repeating `FindObjectsByType` walk.
- `BeanAnimator.LateUpdate` raycasts and reads velocity (`BeanAnimator.cs:116-123`). `GetComponent<BeanController>()` runs once if the controller was added after `Awake` (`:119`).

`LevelSetSpawner.Rebuild` would be a hitch if finding 1 stopped skipping it: `DestroyImmediate` of every child (`:164-165`) and, in play mode, `StaticBatchingUtility.Combine` (`:143-146`) over 1346–5422 objects.

### 15. Physics setup

Project gravity is `(0, -22, 0)` (`ProjectSettings/DynamicsManager.asset:7`). Fixed timestep is the rational `2822399 / 141120000` seconds (`ProjectSettings/TimeManager.asset:8` and `:11`), which is `0.0199999929` s, 50 Hz. Solver iterations are 6 and solver velocity iterations are 1 (`DynamicsManager.asset:14-15`).

The scene bean matches the play numbers: mass 0.9, linear damping 0.18, angular damping 0.9 (`Escape.unity:138801-138803`), interpolate 1 (`:138817`), collision detection 1 (`:138819`), capsule radius 0.38 and height 0.86 (`:138789-138790`). Interpolate 1 is `RigidbodyInterpolation.Interpolate`. Collision detection 1 is `CollisionDetectionMode.Continuous`. Constraints in the file are 80 (`:138818`), which is `FreezeRotationX | FreezeRotationZ`.

`BeanImpulse.Awake` sets the same interpolate and continuous modes (`BeanImpulse.cs:18-19`) and the same rotation lock (`:20`). It does not null-check `GetComponent<Rigidbody>()` (`:17`). The scene object has a body, so this does not throw today.

`BeanController` is not on the scene bean. `GameSession.SetPhase` adds it when `BeanImpulse` is present and no controller exists (`GameSession.cs:54-56`). `BeanController.Awake` then replaces constraints with `FreezeRotation | FreezePositionZ` (`BeanController.cs:74`) and does not set interpolation or collision mode itself. `Start` disables `BeanImpulse` (`:81-84`).

`BeanImpulse.Update` impulses `Vector3.forward` (+Z) plus up (`BeanImpulse.cs:32`). The level runs on +X and the goal test is `bean.position.x` (`LevelRunner.cs:149`, `:164`). That +Z impulse is unused while the controller is enabled. It is the wrong axis if the controller is ever absent.

`LandFeel.FixedUpdate` reads `body.linearVelocity` with no null check (`LandFeel.cs:37`). Its ground ray includes triggers (`:64-66`). `BeanController.CheckGrounded` ignores triggers (`BeanController.cs:213`). `LandFeel` is on the scene bean (`Escape.unity:138750`).

### 16. Save and unlock

`PlayerProgress` stores two clamped ints, `escape.unlocked` and `escape.last` (`PlayerProgress.cs:7-26`). There is no bean total, no per-level record, and no version key. `ClearBeat` unlocks `levelId + 1` only when `levelId >= Unlocked` and `levelId < LevelCount`, then sets `LastPlayed` (`:31-33`). Beating L5 does not move `Unlocked` past 5. Beating L4 while `Unlocked` is still 1 would set `Unlocked` to 5.

`SearchMenu.Refresh` marks locked rows non-interactable (`SearchMenu.cs:49-51`), so the button path cannot do that. `GameSession.PlayLevel` does not read `Unlocked` (`GameSession.cs:69-78`). `Continue` plays `LastPlayed` (`:81`), which `ClearBeat` sets to the level just finished, so Title → Continue replays the cleared level. Next on the clear screen is what advances (`GameSession.cs:91-94`, `TitleFlow.cs:116-126`).

`NewGame` sets both keys back to 1 (`GameSession.cs:83-87`).

### 17. Stale L2 gap comment

`LevelRunner.L2Edges` is `{ 3, 11.30, 12.50, 18.40, 19.75, 27 }` (`LevelRunner.cs:41`), so the gaps are 11.30–12.50 and 18.40–19.75. The comment on `:39` and the spawner comment on `LevelSetSpawner.cs:239` still say the first gap is 4.20–5.40. The tree row uses `InFixedGap(L2Edges, ...)` (`LevelSetSpawner.cs:311`), so it follows the array. A layout pass that follows the comment will dress the wrong interval.

### 18. Small null and input edges

- `TitleFlow.HideAll` calls `_title.SetActive` with no null check (`TitleFlow.cs:323`). `Start` builds the panels before `ShowTitle` (`:46-47`). A `ShowTitle` from outside before `Start` throws.
- `BeanController` and `LandFeel` assume a `Rigidbody` on the same object (`BeanController.cs:72-74`, `LandFeel.cs:24` and `:37`).
- `Pickup` only collects a collider that has `BeanImpulse` on itself or a parent (`Pickup.cs:37`). The scene bean has that component even after it is disabled, so collection works. A bean with only `BeanController` would not collect.
- `accelerometerFrequency` is 60 (`ProjectSettings.asset:14`). No script reads the accelerometer.
- `Screen.sleepTimeout = NeverSleep` (`GameSession.cs:44`) keeps the backlight on for the whole session.

## Tests

`Packages/manifest.json` did not list `com.unity.test-framework`. The lockfile already resolved builtin `1.8.0`, and that version is now a direct dependency.

The suite is new files under `Assets/Tests/` (EditMode and PlayMode asmdefs, plus a small shared asmdef). Gameplay scripts stay in the predefined `Assembly-CSharp` assembly. A test asmdef cannot reference that assembly, and adding an asmdef under `Assets/Scripts` would move every gameplay script. The tests resolve `LevelCatalog` and `PlayerProgress` by reflection.

`GravityScale_StrictlyAscending` is expected to fail on current `Make()` data. The other checks (count, `goalZ`, density, L5 boss, config fields, `RebuildAll`/`Get`, pack search, `PlayerProgress` round-trip and clamp) match the code as read. They were not executed. No Unity editor binary is on this machine (`ProjectSettings/ProjectVersion.txt` is `6000.6.4f1`, and `Unity` is not installed). Do not treat this document as a green test run.
